# Mobile/Touch UX audit of the generated APKs — Hidden Object Engine

Date: 2026-06-21. Branch: `fix/editor-critical-bugs`.
Goal: bring the APKs generated by the editor up to the level of a professional mobile
Hidden Object Game (HOG) (industry references: June's Journey, Hidden City, Pearl's Peril,
Seekers Notes, The Secret Society).

## Architecture (verified)

The APKs do NOT package the web export. `editor/android_build_system.py` uses
Buildozer / python-for-android inside WSL to cross-compile the Python engine + pygame
(`pygame` recipe, not `pygame-ce`) for `arm64-v8a`. So the "generated UI" on mobile is
the same `engine/` running natively through SDL2. Reference coordinates: 1280x720
(`engine/scaling_manager.py`). On Android the internal rendering resolution is adaptive
with a fixed height of 540 px, GPU upscale via `pygame.SCALED`, vsync=0.

## Product decisions (owner)

- Orientation: **landscape** (consistent with REF 1280x720 and horizontally authored scenes).
- Scene inspection: **pinch-to-zoom + pan** (June's Journey / Hidden City paradigm).
- Minimum device: **mid-range** (~4 GB RAM, 1080p) -> internal 720p budget, adaptive cache.
- Start: **Phase 0 (quick wins) immediately**, then phase by phase.

## What is already good (do not redo)

Safe area/notch via display cutout; drawer HUD with handle/swipe and auto-close;
tap-vs-swipe distinction on release; mobile hint button in the bar; pause/resume
lifecycle on `APP_*BACKGROUND`; contextual Back key `K_AC_BACK`; click anti-spam;
hidden cursor + screensaver off; HUD fonts x1.5 on Android. Professional-grade build
toolchain (API 35, arm64, NDK 28.2, p4a fast path, stall watchdog).

## Diagnosis: the dominant gaps

1. **No scene inspection (critical).** `set_zoom`/`set_pan`/`screen_to_scene` exist in
   `ScalingManager` but are dead code; `MULTIGESTURE` is blocked (`core.py:133`). On a
   6" phone small objects are effectively impossible to find.
2. **Pixel-exact hit test with no tolerance (critical).** `ClickDetector.detect` requires
   exact precision; a tap a few px off is a penalized miss.
3. **Fixed 540p internal rendering + nearest upscale (weak).** UI pre-shrunk to 0.75x:
   grainy objects and text, a fatal flaw for a "looking" genre.
4. **Logic bug:** clicking a correct goal beyond the 7th visible one counted as an error
   (`core.py:590` + `_max_visible=7` window).
5. Missing: haptics, juicy micro-interactions on find, ICON list (text today), onboarding,
   sticky immersive mode, audio focus, save-on-background, release keystore, adaptive icon / Splash API.

## Roadmap

### Phase 0 — Playability quick wins (COMPLETED 2026-06-21)
- [x] Fat-finger tolerance: `ClickDetector.detect(slop_screen=...)` with nearest-goal fallback
  in bg space (`_edge_distance`) + `ScalingManager.screen_dist_to_bg` helper.
- [x] Near miss within tolerance: snap to the goal (it becomes a find), no penalty.
- [x] Fix for the penalty on goals outside the window of 7: removed the `is_target_active` gate
  in `core._process_scene_click` (every valid unfound goal registers the find).
- [x] Pause hit rect/visibility at >= 48 dp equivalents on Android (`hud_manager`).
- [x] `SDL_HINT_RENDER_SCALE_QUALITY=1` + `linear` texture filtering on Android.
- Tests: `tests/test_coordinate_system.py::TestFatFingerTolerance` (6 tests, green).
- Slop used: `res_h * 0.045` (~7 mm) only on Android; desktop mouse unchanged (slop 0).

### Phase 1 — Scene inspection (COMPLETED and VERIFIED 2026-06-21)
Pinch-to-zoom + two-finger pan, plus one-finger pan when zoomed in.
- Camera embedded in the `ScalingManager` affine background->screen transform
  (`_base_bg_*` vs effective `_bg_*`, `_recompute_camera` with pan clamped to the edges, `set_zoom`/
  `pan_by`/`zoom_at`/`reset_pan_zoom`): BG rendering, objects, effects, glow and hit test follow
  the camera with no change to the drawing code. Zoom 1.0..3.0 (mid-range).
- Input via `FINGER*` events (real multitouch) in `core._handle_finger_down/motion/up`;
  the one-finger tap stays on the emulated mouse (graceful degradation if FINGER events do not arrive).
- The "no tap/penalty from gestures" constraint is guaranteed by: a `_gesture_seen` flag active while
  fingers remain in contact; one-shot actions (hint/handle/pause/object) deferred to the filtered
  RELEASE; slop on the one-finger pan; camera locked during the scene intro; state reset at
  scene start. Zoom from the original BG for sharpness.
- Tests: `TestInteractiveCamera`, `TestGestureStateMachine` in `tests/test_coordinate_system.py`.
- Later: "pinch to zoom" coachmark (with the Phase 3 onboarding); possible double tap. NB:
  `screen_to_scene` (REF space) remains orphaned/dead code, not used by the hit test.

### Phase 2 — Sharpness and readability
`internal_h` at 720 (REF-aligned, scale 1.0) with a dynamic budget for devices >= 1080p; evaluate
a UI/text layer at native resolution separate from the background; pre-resize assets at export;
fonts in real dp via DisplayMetrics instead of the fixed 1.5x factor.

### Phase 3 — Premium HOG feel (COMPLETED and VERIFIED 2026-06-21)
- ICON object list: `hud_manager._draw_mobile_icons/_draw_icon_tile/_get_icon_thumb`
  (thumbnails cached from `obj.icon_surface`, caption, initial fallback). Replaces the text
  chips. Animated found: scale pop + check mark + fade (`_found_anim`), with a brief auto-open
  of the drawer on a find to make it visible. Tile cap for readability.
- Haptics: `engine/haptics.py` (no-op on desktop, pyjnius Vibrator), called in core on
  found/miss/success_strong. VIBRATE permission in `editor/android_build_system.py` (spec + p4a).
  "VIBRATION" toggle in the settings (Android only), persisted via SaveManager (writable store
  on Android, NOT config.ini).
- Onboarding: first-run coachmark (`core._draw_coachmark`), gated by `coach_seen` via SaveManager,
  Android + SCENE only; the first interaction CLOSES and consumes it (no accidental tap/penalty);
  it does not overlap the intro bubbles; auto-dismiss after 7 s. `coach_*` keys in it.json/en.json.
- Verification: adversarial review (verdict: ready with minor fixes); 2 must-fix resolved (coach
  closing tap consumed; vibration persistence via SaveManager). Tests: `tests/test_haptics.py`.
- Not included (follow-up): fly-to-list scene->HUD; persistent floating hint in the thumb zone;
  centralized config persistence (audio/display have the same read-only limit on Android).

### Phase 4 — Navigation and system
Drag-to-scroll with inertia in the menus + action commit on release; tap targets anchored to the
safe area and >= 48 dp; save snapshot on `APP_WILLENTERBACKGROUND`; sticky immersive mode via
`WindowInsetsController` re-applied on foreground; audio focus centralized in `AudioManager`.

### Build & test on device (2026-06-21)
- Per-game asset pruning in the Android build (`_compute_kept_engine_assets` + prune in
  `_prepare_workspace`): removes the shared `engine/assets` library not used at runtime
  (scene-local bg, game-local icons). LineVenture APK **558 -> 135 MB**.
- pygame build fix: "Patch 3" now patches the **p4a recipe** (`prebuild_arch` injects the SIMD
  blitters into the Setup template before compilation), solving the
  "alphablit_alpha_sse2_* symbol not found" bug that crashed the app at `pygame.display`.
- **Validated on the emulator** (Pixel_10 AVD, x86_64 + ARM translation): the game boots, menu,
  hidden-object scene (9 objects), input/tap, minigame, object found, and the Phase 3 ICON list
  with thumbnails + timer/score/progress + HINT. Build command:
  `python editor/android_build_manager.py <game> <ver> <dir> <status.json>`.
- Polish: `hud_hint` i18n key added (5 languages); `UI_Forbidden.wav` (missing) ->
  `error4.mp3` in core.py.

### Performance optimizations (post-audit, 2026-06-21)
Multi-agent perf audit: on Android the cost was UNCACHED per-frame operations
(the "rich" effects were already gated). Interventions (desktop unchanged):
- Scene objects (core.py): quantized cache key (no invalidation on every pixel of
  pinch-zoom), `convert_alpha` once, MAX_ICON_DIM 1600 on Android, logger removed from the
  hot path.
- HUD (hud_manager.py): composed icon tiles CACHED; memoized info-row texts;
  DIRTY FLAG on the bar (`_hud_surf` recomposed only on content change, otherwise blit).
- Menus (menu_theme.py / cyber_neon_skin.py): cyber_neon title CACHED (no longer ~50
  font.render per frame); button shadows/glow OFF on Android; "glass" button fill
  CACHED per size/state.
- Intro zoom (core.py): render_target reused (no full-screen alloc per frame) + `scale` instead
  of `smoothscale` on Android.
- Slot (slot_classic_game.py): background (fill + rays) pre-rendered and cached; ambient radial
  glow and symbol motion blur OFF on Android.
Results measured on the swiftshader emulator: scn_hud 27->20 ms, scn_obj 15-18->~6-10 ms,
slot 10->14 FPS (then cached background). NB: the software emulator caps the FPS; on a real
device with a hardware GPU the gains translate into much higher frame rates.

### Phase 5 — Publishable packaging
Monotonic `android.numeric_version`; release keystore config (`P4A_RELEASE_*` env) + editor
dialog; adaptive icon (foreground/background) + Splash API/`presplash_color`; single packaging
config shared between `_generate_buildozer_spec` and `_get_p4a_apk_command`; expose
`orientation` in `game_config.json`.

### Phase 6 — Performance and minigames
On-demand/dirty-frame rendering + evaluate vsync=1 instead of `tick_busy_loop`; move
`convert()/convert_alpha()` to the main thread; RAM-adaptive surface cache + `onTrimMemory`;
`TouchControls` as a contract in `BaseMinigame`; fix the touch controls of
asteroids/centipede/minipong/spot-differences.

## Open decisions (to clarify before the related phases)

- Near miss: snap to the goal (chosen for Phase 0) or just no penalty; fate of the miss penalty.
- Window of 7 objects: removed entirely (scrollable list) or visual viewport only.
- Rendering: quick win only (720 + linear) or a separate UI layer at native resolution.
- Keystore: manual handling from the editor or Play App Signing; where to keep the credentials.
- BG video on mobile (cv2 disabled): forbidden or mandatory static poster per scene.
