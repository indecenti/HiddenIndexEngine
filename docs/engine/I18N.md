# Localizzazione (engine + editor)

Regole vincolanti del sistema multilingua di HiddenIndexEngine.

## Lingua di default e fallback

- **Default**: inglese. `engine.language_manager.DEFAULT_LANG == "en"` e
  `editor.constants.DEFAULT_LANG == "en"`. Vale quando non esiste una
  preferenza salvata (`.editor_settings.json` per l'editor, `config.ini` per il
  gioco, `default_language` in `game_config.json`) o quando quella salvata non
  e' piu' fra le lingue supportate.
- **Fallback**: sempre inglese. `engine.language_manager.FALLBACK_LANG == "en"`.
  `LanguageManager.load_for_game(..., fallback=...)` ignora (con warning)
  qualsiasi valore diverso: l'inglese e' l'unica lingua garantita completa, e
  una chiave mancante in `it/fr/es/de` deve degradare in inglese, mai alla
  chiave grezza.

Ordine di risoluzione di `LanguageManager.get(key, default)`:

```
game_strings -> engine_strings -> fallback EN -> default inline -> chiave
```

Lingue supportate dall'editor: `editor.constants.LANGS = ("en", "it", "es", "fr", "de")`.
I file stanno in `engine/assets/strings/<lang>.json`; `ja/ko/pt/ru/zh` esistono
solo con i nomi oggetto e ricadono su EN per tutto il resto.

## Come si scrive una stringa nell'editor

Mai testo hardcoded nelle chiamate di rendering. Si usa sempre una chiave con
il **default inglese inline**, che funge da rete di sicurezza se la chiave non
e' ancora nei file lingua:

```python
_draw_text(self.screen, self._TR("sc_lbl_style", "Catalog style"),
           "sm", TXT_DIM, x, y)
```

Con valori variabili si usa `str.format` con **placeholder nominali**, non
f-string: il testo tradotto deve poter riordinare i segnaposto.

```python
self._status(
    self._TR("io_scene_loaded", "Scene: {name}  ({n} objects)").format(
        name=scene_path.name, n=n), OK_C, 3)
```

Componenti che non sono mixin dell'editor (modali standalone come
`ColorPickerModal`, `_BatchImportModal`) non hanno `self._TR`: usano il
`LanguageManager` attivo registrato a livello di processo.

```python
from engine.language_manager import tr

_button(screen, rect, tr("btn_apply", "Apply"), hovered)
```

`set_active_manager(...)` viene chiamato dall'editor (`editor_base`) e dal
gioco (`engine.core`) subito dopo `load_for_game`.

## Prefissi delle chiavi

| Prefisso | Area |
|----------|------|
| `sc_` | modale auto-scatter |
| `gs_` | selettore progetti / livelli / scene |
| `img_` | studio asset (editor immagine) |
| `ih_` | scorciatoie e messaggi di `input_handlers` |
| `io_` | caricamento/salvataggio, autosave, catalogo |
| `obj_` (non `obj_<id>`) | operazioni su oggetti della scena |
| `prop_`, `cat_`, `fx_`, `tab_`, `layers_` | pannelli |
| `aud_`, `st_`, `bi_`, `lm_`, `nob_`, `ico_`, `tg_`, `cp_` | modali dedicati |
| `menu_`, `tb_`, `btn_`, `badge_`, `modal_`, `tip_` | chrome comune |
| `obj_<id>`, `tag_<id>`, `ca_<id>_name` | nomi oggetti e tag del catalogo |

## Contratto verificato dai test

`tests/test_editor_i18n.py` fallisce se:

1. una chiave usata dal codice (`self._TR`, `lang_manager.get`, `tr`) manca in
   una delle 5 lingue, o ha valore vuoto;
2. i segnaposto `{...}` di una traduzione non coincidono con quelli inglesi
   (una traduzione che ne perde uno fa esplodere `str.format` a runtime);
3. una chiave UI esiste in una lingua e non nelle altre;
4. un valore contiene sequenze da UTF-8 letto come latin-1 (`Ã`, `â€`, `â†`);
5. `DEFAULT_LANG` o `FALLBACK_LANG` non sono `"en"`.

Aggiungere una stringa nuova significa quindi: chiave + default inglese inline
nel codice, e una riga in **tutti e cinque** i file di
`engine/assets/strings/`.

## Harvesting verso i giochi

Al salvataggio della scena l'editor copia nel `games/<id>/strings/<lang>.json`
le chiavi effettivamente usate dal gioco (oggetti, HUD, menu), cosi' il gioco
resta distribuibile standalone. Le chiavi di sola UI dell'editor (`sc_`, `gs_`,
`img_`, ...) restano in `engine/assets/strings/` e non vengono copiate.
