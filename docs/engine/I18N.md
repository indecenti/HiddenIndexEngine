# Localization (engine + editor)

Binding rules of HiddenIndexEngine's multi-language system.

## Default language and fallback

- **Default**: English. `engine.language_manager.DEFAULT_LANG == "en"` and
  `editor.constants.DEFAULT_LANG == "en"`. It applies when no saved preference
  exists (`.editor_settings.json` for the editor, `config.ini` for the game,
  `default_language` in `game_config.json`) or when the saved one is no longer
  among the supported languages.
- **Fallback**: always English. `engine.language_manager.FALLBACK_LANG == "en"`.
  `LanguageManager.load_for_game(..., fallback=...)` ignores (with a warning)
  any other value: English is the only language guaranteed to be complete, and
  a key missing in `it/fr/es/de` must degrade to English, never to the raw key.

Resolution order of `LanguageManager.get(key, default)`:

```
game_strings -> engine_strings -> EN fallback -> inline default -> key
```

Languages supported by the editor: `editor.constants.LANGS = ("en", "it", "es", "fr", "de")`.
The files live in `engine/assets/strings/<lang>.json`; `ja/ko/pt/ru/zh` exist
only with the object names and fall back to EN for everything else.

## How to write a string in the editor

Never hardcoded text in rendering calls. Always use a key with an **inline
English default**, which acts as a safety net if the key is not yet in the
language files:

```python
_draw_text(self.screen, self._TR("sc_lbl_style", "Catalog style"),
           "sm", TXT_DIM, x, y)
```

With variable values use `str.format` with **named placeholders**, not
f-strings: the translated text must be able to reorder the placeholders.

```python
self._status(
    self._TR("io_scene_loaded", "Scene: {name}  ({n} objects)").format(
        name=scene_path.name, n=n), OK_C, 3)
```

Components that are not editor mixins (standalone modals such as
`ColorPickerModal`, `_BatchImportModal`) do not have `self._TR`: they use the
active `LanguageManager` registered at process level.

```python
from engine.language_manager import tr

_button(screen, rect, tr("btn_apply", "Apply"), hovered)
```

`set_active_manager(...)` is called by the editor (`editor_base`) and by the
game (`engine.core`) right after `load_for_game`.

## Key prefixes

| Prefix | Area |
|--------|------|
| `sc_` | auto-scatter modal |
| `gs_` | project / level / scene selector |
| `img_` | asset studio (image editor) |
| `ih_` | shortcuts and messages of `input_handlers` |
| `io_` | load/save, autosave, catalog |
| `obj_` (not `obj_<id>`) | operations on scene objects |
| `prop_`, `cat_`, `fx_`, `tab_`, `layers_` | panels |
| `aud_`, `st_`, `bi_`, `lm_`, `nob_`, `ico_`, `tg_`, `cp_` | dedicated modals |
| `menu_`, `tb_`, `btn_`, `badge_`, `modal_`, `tip_` | common chrome |
| `obj_<id>`, `tag_<id>`, `ca_<id>_name` | catalog object and tag names |

## Contract verified by the tests

`tests/test_editor_i18n.py` fails if:

1. a key used by the code (`self._TR`, `lang_manager.get`, `tr`) is missing in
   one of the 5 languages, or has an empty value;
2. the `{...}` placeholders of a translation do not match the English ones
   (a translation that loses one makes `str.format` blow up at runtime);
3. a UI key exists in one language and not in the others;
4. a value contains UTF-8-read-as-latin-1 sequences (`Ã`, `â€`, `â†`);
5. `DEFAULT_LANG` or `FALLBACK_LANG` are not `"en"`.

Adding a new string therefore means: key + inline English default in the code,
and one line in **all five** files of `engine/assets/strings/`.

## Harvesting into games

On scene save the editor copies into `games/<id>/strings/<lang>.json` the keys
actually used by the game (objects, HUD, menus), so the game stays shippable
standalone. Editor-only UI keys (`sc_`, `gs_`, `img_`, ...) stay in
`engine/assets/strings/` and are not copied.
